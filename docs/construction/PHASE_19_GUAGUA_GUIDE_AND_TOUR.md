# Phase 19：学院呱呱知识库与教学演示升级

## 用户目标

学院呱呱必须覆盖当前 `model-ccswitch` 产品，而不是停留在早期四工作区版本。用户点击“新手教程”后，第一步先说明 Catnip Forge 是什么、适合谁、各工作区如何协作，再进入分步操作。模型教学排在功能教学最前面；探索、线上 Skill Hub 和模型更换必须足够详细，能让第一次使用的用户独立完成配置。

## 本轮范围

1. 重写 `electron/CATNIP_FORGE_USER_GUIDE.md` 中已经漂移的启动、模型、主界面、探索、Skill Hub 和常见问题说明。
2. 教学演示版本升级，步骤顺序为：项目总览 → 模型配置与切换 → Agent → 仓库 → 探索连接/两种模式/历史/收藏验证 → 线上 Skill Hub → 监视器/任务/编辑器 → 学院呱呱。
3. 为模型页与探索首页补充稳定 `data-tour-id`，让演示能高亮真实功能区域，不依赖中文文本定位。
4. 更新静态专项和真实 Renderer 教学烟测；教程仍不得执行远程调用、保存 Key、修改工程、Build、Flash 或打开串口。

## 必须解释清楚的用户操作

### 模型

- 首启预设路径：DeepSeek Key 必填、Qwen 视觉 Key 选填、原生安全窗口、保存后重启与工作区选择。
- 其他供应商路径：新增、保存、配置 Key、获取模型、一键/逐角色映射、默认兜底、测试、脱敏预览、启用。
- Sonnet、Opus、Fable、Haiku、Subagent、显示名称、实际请求模型、1M 的含义。
- Chat 输入框只能切换当前活动供应商真实返回的模型；供应商切换在模型页完成；新任务生效、运行中/排队任务不变。
- 所有 Key 可替换或清除，Renderer/普通配置/预览不显示 Secret。

### 探索

- 知乎官方 Skill 的安装、个人中心 Access Secret、安全窗口、连接四态、替换/在线验证/退出本机登录。
- 找灵感用于把模糊想法变成结合当前工程与硬件约束的可落地方向；解问题用于结合用户勾选的工程/设备/日志/历史知识和知乎＋全网来源交叉诊断。
- 每工程、每模式、多会话历史的创建、恢复、重命名、删除和中断状态。
- 收藏是用户主动操作；本地知识不会自动进入 Context。解问题只显示相关候选，用户勾选后才使用。
- 验证状态记录“有效/无效”、验证方式、结果和备注，形成长期可纠错知识；Catnip 本地知识库不等于知乎官方知识库。
- 探索只分析，计划/交接/确认提交与工程 Agent 执行门禁必须明确。

### 线上 Skill Hub

- 网页用于发现和下载；本地“仓库”中的 Skill Manager 用于查看、编辑、同步和实际部署。
- 网页内容不自动成为 Agent Context，不获得任意本地文件权限；下载后应回仓库核对并同步。

## 验收

- `verify:software-assistant-guide`：检查当前模型安全逻辑、五角色、探索连接/历史/收藏验证、Skill Hub 边界。
- `verify:onboarding`：检查项目总览为第一步、模型早于 Agent/探索、探索至少覆盖连接/模式/历史/知识验证。
- `typecheck`、`build:renderer`、`verify:onboarding-ui`；若发布 Chromium 缺失，必须记录真实阻塞，不以静态测试冒充。
- 人工重播教学，确认步骤文字可读、目标可见、返回/退出/重播正常。

## 安全与非目标

- 教程不要求用户把 Key 或 Access Secret 粘贴进聊天框，只指向 Main 控制的原生安全窗口。
- 不调用真实付费模型、知乎搜索或硬件动作；不改变 Explore/Agent/Skill 的执行架构。
- 不触碰 `docs/tutorials/` 和硬件工程 `.catnip/` 用户现场。
