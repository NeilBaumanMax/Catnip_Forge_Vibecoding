# Catnip Forge 软件使用手册

> 本文是内置软件助手“Neil·Bauman's 学院呱呱”的产品知识来源。开发版修改后，学院呱呱下一次回答会重新读取；发布版使用 `resources/CATNIP_FORGE_USER_GUIDE.md`。任何 API Key 或 Access Secret 都不要粘贴进学院呱呱或 Agent 聊天框。

## 1. 先认识整个项目

Catnip Forge 中文定位是“Catnip 硬件智能开发平台”，英文定位是“Autonomous Hardware Development Agent”。当前发布版为 v2.0.0，内部构建号 7201。它面向使用 ESP32、ESP32-S3 等开发板的 Maker、学生和硬件开发者，把创意研究、问题诊断、代码编辑、Agent 开发、编译、烧录与串口验证放进同一个本地桌面工作区。

各区域不是孤立工具，而是一条协作链：

1. 启动时选择当前工程，工程是 Agent、探索、编辑器、任务管理器和串口证据的共同上下文。
2. “模型”决定之后提交给 Agent、找灵感和解问题的任务使用哪个 Claude Code 兼容供应商与模型。
3. 左侧 Agent 负责真正修改文件、执行命令和推进工程任务。
4. “仓库”管理本地 Skills、硬件工程和参考代码；“Neil 的 skill 小站”负责在线发现 Skill。
5. “探索”在动手之前找方向或分析故障，先形成结论和计划，只有用户确认后才交给工程 Agent。
6. “编辑器”查看和修改文件；“任务管理器”执行 Build/Flash；“监视器”查看真实串口输出。
7. 右下角学院呱呱只回答软件怎么用，不直接修改工程、编译、烧录或删除文件。

## 2. 模型配置与更换——首次使用应先完成

### 2.1 第一次打开软件

完整解压便携目录后运行 `Catnip Forge.exe`，不要只复制 EXE。首次尚未配置模型时，启动遮罩提供两条路径：

- “配置 DeepSeek / 千问”：适合大多数用户。DeepSeek API Key 必填，用于 Agent、找灵感和解问题；Qwen API Key 选填，只用于用户主动提交的图片视觉任务。
- “使用其他模型供应商”：进入 Claude Code 供应商管理，适合智谱等提供 Anthropic Messages 兼容接口的服务。

输入 Key 时会打开独立的 Windows 原生安全窗口。Key 由 Main 进程写入 Windows 安全存储，Renderer 页面、普通模型配置、日志、聊天记录和配置预览都拿不到明文。完成首次配置并启用供应商后软件会自动重启，随后要求选择工作区文件夹。Qwen 未配置只会关闭图片理解，不影响纯文本 Agent、探索、编译、烧录或串口。

### 2.2 使用预设 DeepSeek / Qwen

1. 在首次遮罩点击“配置 DeepSeek / 千问”。
2. 在原生安全窗口粘贴 DeepSeek API Key；需要看图片时再填写 Qwen API Key，否则留空。
3. 提交后等待安全存储成功，不要把 Key 发到聊天框。
4. 软件自动重启后选择工程目录进入主界面。
5. 以后打开“模型”标签页，可以查看当前启用供应商、默认模型和 Key 是否已配置。
6. “替换”会打开安全窗口覆盖对应 Key；“清除”会删除本机保存的该 Key。Qwen 是选填项，可以独立替换或清除。

### 2.3 配置其他 Claude Code 模型供应商

当前 Catnip 直连版只支持 Claude Code CLI 能直接使用的 `Anthropic Messages（原生）`接口。需要 CC Switch 本地代理进行 OpenAI Chat/Responses 协议转换、完整 URL 路由、Header/Body 覆盖或 User-Agent 模拟的供应商暂不可用，页面会明确禁用，不能把“能够填写”误当成“能够运行”。

推荐按下面顺序操作：

1. 打开“模型”标签页，点击供应商列表右上角“＋”。
2. 填写“供应商名称”；“备注”可写账号用途；“官网链接”用于记录供应商主页。
3. 填写供应商给 Claude Code 使用的 Base URL。普通前缀模式下，Catnip/Claude Code 会按 Anthropic Messages 规则请求。不要自行把网页官网当成 API 地址。
4. API 格式保持 `Anthropic Messages（原生）`。
5. 选择鉴权变量：第三方服务常用 `ANTHROPIC_AUTH_TOKEN`，Anthropic 官方兼容服务常用 `ANTHROPIC_API_KEY`；必须以供应商文档为准。
6. 填写“默认兜底模型”。Claude Code 未明确命中某个角色映射时使用它。
7. 先点击“保存更改”。新供应商保存后才会得到独立的安全凭据槽。
8. 在 API Key 卡片点击“配置”，在弹出的 Windows 安全窗口输入该供应商 Key。
9. 点击“获取模型列表”。Main 会使用该 Key 尝试显式模型列表 URL，或按 `/v1/models`、`/models` 等候选读取真实模型 ID；结果只作为输入框候选。供应商没有列表接口时仍可手工填写文档给出的模型 ID。
10. 配置角色映射。可点击“一键设置”让所有角色先使用同一模型，再逐行调整。
11. 点击“测试配置”。该动作会明确发起一次最小的 Anthropic Messages 请求，用于验证地址、Key 和默认模型；成功状态才表示在线接口实际可用。测试可能产生极少量供应商调用费用。
12. 点击“配置预览”，核对请求 URL 和将写给 Claude Code 的环境变量。预览里的 Key 始终是安全占位符。
13. 点击“启用此供应商”。启用后，Agent、找灵感和解问题在下一次新任务提交时使用它；正在运行和已排队任务继续使用创建时冻结的旧供应商/模型。

### 2.4 五种角色映射分别是什么

- Sonnet：Claude Code 默认的均衡主力角色，通常映射到供应商的通用编程模型。
- Opus：偏复杂推理或高能力角色，可映射到供应商的高性能模型。
- Fable：Claude Code 可识别的另一角色映射；不确定时可与默认或 Opus 使用同一模型。
- Haiku：偏快速、低成本角色，适合映射到 Flash、Air、Lite 等快速模型。
- Subagent：Claude Code 子任务/子代理使用的模型；通常选择速度和成本更合适的模型。
- “显示名称”只改变 Claude Code `/model` 菜单里给用户看的文字，不会改变供应商收到的真实 `model`。
- “实际请求模型”必须填写供应商真正接受的模型 ID。
- “1M”会给支持的角色模型添加 `[1m]` 长上下文标记；只有供应商和对应模型确实支持时才启用。Haiku 行不提供 1M。
- “默认兜底模型”独立于角色行；任何角色留空时会回到兜底模型。

### 2.5 在 Agent 输入框切换模型

Agent 输入框下方的模型按钮显示“当前活动供应商 · 当前模型”。点击后，软件用当前供应商的安全 Key 查询该 Key 实际可用的模型；选择某项会更新应用级当前模型，并把五个角色统一切到该模型。它不是当前聊天私有设置：之后新建的 Agent、找灵感和解问题任务共同使用。这里不能跨供应商，跨供应商必须回“模型”标签页启用另一供应商。

如果列表为空或报错，依次检查 Key、网络、供应商模型列表 URL和权限。不要凭名称猜测“Pro/Flash 一定存在”，只有供应商对当前 Key 返回的模型才可在输入框安全切换。

## 3. 启动、工程选择与主界面

首次模型配置完成后的正常冷启动顺序是：启动动画 → 工作区选择 → 主界面，不会每次重新显示 Key 配置。工作区选择是显式门禁，因为工程决定 Agent 历史、探索历史、编辑器内容和硬件任务的归属。

主界面左侧是 Agent 对话；右侧有七个标签页：仓库、监视器、任务管理器、编辑器、探索、模型、Neil 的 skill 小站。正在执行工程任务时不要无提示切换工程。全局 Skills 和本地知识可以跨工程发现，但只有用户主动选择后才进入某次任务 Context。

## 4. Agent 对话、模型状态与历史

- 在左侧输入框描述要实现或修复的任务，Enter 发送、Shift+Enter 换行。Agent 会使用提交瞬间冻结的活动供应商、模型、工程和 Skills。
- Agent 工作期间再次发送可以追加要求；需要等待独立执行时使用排队。切换模型不会中途替换运行中或已排队任务。
- “专业视图”展开工具、状态和诊断细节；关闭只改变显示，不删除执行记录。
- “附件”支持图片、PDF、DOCX、PPTX、TXT、Markdown、JSON 等；图片视觉理解需要 Qwen Key。附件只在用户主动发送后进入任务。
- “＋ Skills”或输入 `@` 可搜索并插入一个或多个 Skill 引用；退格可完整删除光标前的引用。
- 历史对话会持久化。使用“新对话”创建独立会话；从历史列表恢复旧会话；“⋯”支持重命名、置顶/取消置顶和删除。删除会二次确认。
- 真正修改代码、创建文件、Build、Flash 或操作串口时使用 Agent，不要让学院呱呱执行。

## 5. 探索总览与知乎连接

“探索”是独立研究工作区，只有“找灵感”和“解问题”两个入口。它复用当前工程、现有 Agent、Skills、Runtime MCP 与 Hardboard，但对话和历史独立于左侧 Agent。探索阶段只分析；没有经过计划预览和用户确认，不得修改工程或执行 Build/Flash/Serial。

### 5.1 知乎连接逻辑

探索使用随包的知乎官方目录型 Skill 和官方 CLI，不自行重建知乎 API。打开探索首页时，Main 会先运行官方 `status` 检查，页面只显示四类状态：

- “已连接”：官方 CLI 已安装、版本兼容、Access Secret 已配置。仍可点击“在线验证”确认当前 Secret 可用。
- “需要 Access Secret”：CLI 已就绪但没有有效凭据。点击连接后会打开知乎个人中心和独立 Windows 安全输入窗口。
- “需要安装”：本机缺少兼容 CLI。点击安装代表用户授权从知乎官方地址下载、校验并安装到当前用户目录；不需要管理员权限，也不修改 PATH。安装完成后再进入 Secret 安全输入。
- “错误”：状态检查失败。先阅读页面提示，检查网络和 CLI，再点“重新检查”。

首次连接步骤：

1. 打开“探索”，查看顶部知乎连接状态。
2. 如提示安装，点击安装并等待官方 CLI 下载与校验完成。
3. 点击连接，系统浏览器打开知乎个人中心；在网页生成新的 Access Secret。
4. 将 Secret 只粘贴到随后出现的原生安全窗口，不要粘贴到探索对话或学院呱呱。
5. 提交后页面轮询官方状态，成功后显示已连接。
6. “在线验证”用于重新验证当前 Secret；“替换 Secret”用于凭据到期或主动轮换；“退出本机登录”清除当前电脑上的知乎登录。所有配置都可以维护，不是一次性向导。

Access Secret 的网页申请属于知乎账号流程；Catnip 不在 Renderer、URL、日志、截图、聊天或本地知识卡中保存明文。

## 6. 找灵感：把模糊想法变成可实现方向

找灵感适合“我想做一个桌面环境监测器，但不知道怎样设计”“这个 ESP32-S3 工程还能做什么”等开放问题。它不是随机生成点子，而是把当前工程与硬件约束、知乎社区经验和必要的全网资料结合起来，输出多个有来源、能比较、可继续落地的方向。

操作流程：

1. 在探索首页点击“找灵感”，或从历史中新建一条灵感记录。
2. 描述目标、使用场景、已有硬件、成本/功耗/尺寸等限制。越具体，候选方向越可执行。
3. 检查自动发现的当前工程和硬件 Context；只保留愿意用于本次分析的项目。发现不等于自动使用。
4. 启动分析。找灵感要求知乎来源，必要时补充全网来源；来源不可用时会明确提示，不静默伪造。
5. 查看多个“可实现方向”：价值、实现路径、与现有工程兼容性和来源证据。点击来源可在外部页面核对。
6. 选择一个 Idea 后进入计划阶段。探索 Agent 只生成计划与交接材料，不直接改代码。
7. 检查 `PLAN.md`、`HANDOFF.md` 等材料；只有点击“确认提交给工程 Agent”，工程 Agent 才能开始执行。

找灵感适合做方向选择，不适合替代真实硬件验证。一个想法被选中不代表已经编译、烧录或在设备上运行。

## 7. 解问题：用工程证据和外部经验交叉诊断

解问题适合编译错误、烧录失败、串口异常、设备运行不符合预期、功耗/通信/驱动问题等。相比直接问 Agent，它先收集和筛选证据、比较多个假设，再形成可审查的排查计划；对运行异常和原因不明确的问题尤其有价值。

操作流程：

1. 在探索首页点击“解问题”，也可以从任务管理器失败项或串口异常入口带着问题描述进入。
2. 清楚描述“预期是什么、实际发生什么、何时开始、如何复现、已经尝试什么”。不要只写一个错误码。
3. 等待 Context 收集后逐项勾选。候选可能包括工程、目标芯片、硬件、源码摘要、Build 结果、串口事件和本地知识。取消勾选的内容不会进入分析。
4. 本地知识区只展示与当前问题相关的候选；用户必须再次勾选，历史收藏才会成为本次 Context。
5. 启动分析。解问题要求知乎与全网两类来源交叉判断，并结合本地工程证据输出优先假设、支持/冲突证据和下一步验证方式。
6. 与探索 AI 继续对话，补充现象或要求比较假设；对话属于这条探索记录，不会混进左侧 Agent 历史。
7. 确认诊断后生成排查计划与交接材料。检查计划是否会修改文件、编译、烧录或使用串口。
8. 最后一步先预览落盘材料，只有用户明确确认提交，工程 Agent 才执行。执行完成不等于硬件验证完成；需要真实 Build/Flash/Serial 证据才能标记相应状态。

## 8. 探索对话历史怎么用

- 找灵感和解问题按“当前工程 + 模式”分别保存多条记录，不是每种模式只保留最后一条。
- 进入任一模式会创建或打开独立会话；草稿、勾选的 Context、对话、来源、结构化结论、选中 Idea、计划、交接和阶段都会保存。
- 返回探索首页、切换标签页、Renderer 重载或软件重启不会自动清空记录。回到首页，在“最近的探索记录”点击一条即可恢复。
- “新建灵感”和“新建调查”创建新的空白会话，不覆盖旧记录。
- 可重命名记录，让标题反映具体主题；删除只删除所选探索会话，不会连带删除已经主动收藏的本地知识。
- 运行中请求会按 requestId 写回原会话。应用重启导致请求无法继续时应显示已中断、可重试，不会永久假装运行，也不会把结果写入新工程。
- 历史保存在当前工程的 `.catnip/explore/<模式>/<会话 ID>/session.json`；不要手工批量改这些文件，优先使用界面操作。

## 9. 本地收藏与知识库验证

Catnip 的“我的知识库”是本机长期知识卡，不等于知乎官方 Knowledge Base，也不会批量镜像知乎全文。

### 9.1 收藏

1. 完成找灵感或解问题分析后，在可信来源旁点击“收藏到知识库”。
2. 知识卡保存来源类型、标题、作者、原 URL、任务相关摘要、标签、备注、关联工程、收藏时间和当前验证状态；默认不保存整篇网页。
3. 如果收藏来自一次探索，会保存该次探索对话的有界本地快照。“查看原对话”用于回顾当时为什么收藏。
4. 收藏不会自动加入后续任务，也不会因为相关性高就偷偷进入 Context。

### 9.2 在解问题中使用

描述问题后，软件会从本地收藏中发现相关候选。只有勾选的知识卡才进入本次诊断 Context；问题文本变化时旧选择会失效，需要重新确认。这能避免过时或无关经验污染判断。

### 9.3 记录真实验证

1. 在知识卡点击“记录验证”。
2. 必填“实际做了什么、观察到什么结果”；可填写任务 ID、日志时间、串口片段等证据引用。
3. 选择“验证有效”或“验证无效”。无效记录不会被删除，它用于提醒以后不要重复使用错误经验。
4. 每次验证追加一条记录，卡片展示最近验证摘要。没有实机证据时不要声称硬件已验证。
5. “删除收藏”会二次确认，只删除知识卡，不删除原探索历史。

## 10. Neil 的线上 Skill 小站

“Neil 的 skill 小站”在内置浏览器中打开固定 Skill Hub，用于在线发现和下载可扩展 Agent 能力。正确心智是“线上发现，本地管理”：

1. 打开“Neil 的 skill 小站”，按分类或说明了解 Skill 的用途、依赖和来源。
2. 下载或安装前确认它是否适合当前任务；网页内容不会自动成为 Agent Context，也不能任意读写本地工程。
3. 完成下载后回到“仓库”标签页的 Skill Manager，检查本地 Skill 文件和 `SKILL.md`。
4. 需要时编辑说明，再点击“立即同步”部署给 Agent。只有已经同步、且在对话中主动选择或引用的 Skill 才参与任务。
5. 更新同名 Skill 前先确认覆盖影响；来源不明或要求提交 Secret 的 Skill 不应安装。

当前小站固定地址为 `http://118.195.247.102/#page-top`。小站不是第二套 Agent、任务系统或云端工程；本地 Skill Manager 仍是实际管理与同步入口。

## 11. 仓库、编辑器、任务管理器与监视器

### 仓库

“仓库”集中显示 Skills、硬件工程和参考代码。硬件工程是可编辑/编译/烧录的项目；参考代码是 ESP-IDF 示例与片段；Skills 是 Agent 工作流。打开目录可在资源管理器查看，编辑 Skill 后保存并同步。

### 编辑器

编辑器只访问受控工作目录，提供文件树、多标签、语法高亮、保存和字号调整。先保存修改再编译；删除文件会进入系统回收站。需要大空间时可收起左侧 Agent 或拖动分隔线。

### 编译与烧录

1. 打开“任务管理器”，点击“刷新工程”，选择工程，再点击“编译”。
2. 查看实时日志、进度、退出码和最近任务。失败项可进入解问题继续分析。
3. 烧录前点击“刷新设备”，选择真实 COM 口；确保编译产物和目标板正确，再点击“烧录”。
4. “清除记录”清除任务历史和相关运行日志，不删除工程源码。

### 串口监视器

监视器支持端口刷新、波特率、数据位、停止位、校验位、文本/HEX、GBK/UTF-8/ASCII/Latin1 和发送行尾。常见 ESP32 日志为 115200，但以工程为准。Agent 与界面共用同一 Electron 串口会话；外部串口软件仍可能抢占端口。烧录提示拒绝访问时先关闭外部占用或正在运行的监视器会话。

## 13. 常见问题

### 首次配置页为什么不再出现

模型配置完成后，正常启动只显示启动动画和工作区选择，不会重复索要 Key。以后从“模型”标签页替换、清除或切换供应商。

### 配置其他供应商后 Agent 仍显示旧模型

确认已经依次保存供应商、配置 Key、测试成功并点击“启用此供应商”。切换只影响之后提交的任务；运行中和已排队任务保持旧快照。必要时重启软件后再新建任务。

### 获取模型列表失败

检查 Base URL、模型列表 URL、Key 权限和网络。列表失败不代表 Messages 接口一定不可用，可按供应商文档手填模型 ID并点击“测试配置”。401/403 通常是 Key 或权限问题。

### 知乎一直提示需要 Secret

在知乎个人中心重新生成 Secret，通过探索页“替换 Secret”的原生安全窗口提交，再点“在线验证”。不要把 Secret 输入聊天框。若提示 CLI 不兼容，先按页面引导安装官方版本。

### 探索为什么没有直接修改工程

这是安全门禁。探索负责研究、诊断、计划和交接；必须在最后一步预览材料并由用户确认，工程 Agent 才能执行。

### 为什么收藏没有自动用于新问题

自动发现不等于自动加入 Context。先描述问题，在相关知识区勾选要使用的卡片，再开始分析。

### 串口列表为空或拒绝访问

刷新设备、确认驱动和 Windows 设备管理器中的 COM 口。拒绝访问通常表示外部串口助手、烧录程序或另一个进程正在占用。

### 软件更新后找不到旧对话

历史位于 `%APPDATA%\@Catnip_Forge\electron`。更换 Windows 用户或清理 AppData 后无法自动恢复。模型 Key 位于 Windows 安全存储，不应再按旧版本说明寻找 `resources/apikey.txt`。

## 14. 回答与安全边界

- 不索要、复述、展示或猜测 API Key、Access Secret、Authorization 或密码。
- 不指导用户把 Secret 放入聊天、URL、日志、截图、普通配置或项目文件。
- 不声称学院呱呱已经修改文件、调用模型、连接知乎、编译、烧录或验证硬件。
- 软件显示“配置完整”不等于供应商在线可用；以用户主动测试的真实响应为准。
- 软件测试通过不等于硬件验证完成；Build、Flash、Serial 与实机现象要分别依据真实证据判断。
- 不确定时明确说明不确定，并引导用户查看对应页面或让左侧 Agent做只读检查。
